# 26. PvP (`FEATURES.PvP`, default `true`)

Design: `docs/PVP.md`. `false` = `BuyPvpItem` refused ("PvP is not open yet"), no per-player runtime state, no Player attribute, nothing in `State`.

- **Config:** `Config.PVP` (`CONTROL_MAX_SECONDS` 2, `SLOW_MAX_SECONDS` 3, `CONTROL_IMMUNITY_SECONDS` 3, `MIN_COOLDOWN` 1.5, `PRICE_FACTOR_TOOL` 0.03, `PRICE_FACTOR_FUN` 0.01, `PRICE_FACTOR_TRAP` (one trap charge), `PRICE_MIN` 100, `KNOCKBACK_*`, `CHARGE_*`, `TRAP_*`, `BLOB_*`, `SPLAT_*`, `TRAP_PLACE_RANGE`, `MAP_BOUNDS`), `Config.PVP_FUN` (Fun item tunables, §26.8) and `Config.PVP_TOOLS` (every ladder item: `id` (save key, never rename), `name`, `line` `Knockback | Trap | Blaster | Fun`, `tier`, `rebirths` (a `REBIRTH_TIERS` threshold), `cooldown`, `kind` `tool | fun`, `cosmetic`, plus effect params). `Validate.pvpTools` runs at Config load and asserts: cooldown >= `MIN_COOLDOWN`, control <= `CONTROL_MAX_SECONDS`, slow <= `SLOW_MAX_SECONDS`, a Squirter shot gap >= the `UsePvpItem` rate limit, gates are rank thresholds, no `damage` / `health` field.
- **No safe zones.** PvP works everywhere on the map. There is no `SAFE_ZONES`, no `inSafeZone`, no `SafeZone` event and no `State.pvp.safeZone`.
- **`Shared.PvpRules` (pure):** `price` (factor x `Economy.rebirthCost(gate)`, at least `PRICE_MIN`; a trap charge uses `PRICE_FACTOR_TRAP`), `isUnlocked`, `canBuy` / `buy` (flag, rank, cash, already owned; a trap tier: at most `TRAP_MAX_HELD` charges), `owns` / `bestTier` / `bestTool` (a higher Knockback / Blaster tier supersedes the lower ones; a trap tier is owned while it has a charge), `charges` / `useCharge`, `canControl` / `applyControl` / `applySlow` / `extendSlow` (clamp, then immunity), `ready` / `markUsed` (cooldown registry), `canTarget`, `clampKnockback` (horizontal cap, arc cap, landing inside the map minus a margin). **No PvP item ever reduces Humanoid health.**
- **Who may be hit (`PvpRules.canTarget`):** anyone, anywhere. A target under control or immunity is refused for items that control or slow (gloves still catch a thief, see below). Effects on a player who carries nothing are light (a push, a short slow, a laugh); nobody ever loses anything to them.
- **Hit carrier:** `PvpService.hitCarrier(world, victim, attacker?, now, ctx?) -> string?` is the one way a PvP item makes a player drop the slime they carry (`CarryDrop.knockLoose`, the Bat's path). A stolen slime calls `StealService.escape(..., "slap")` (drop + bounce home + the carrier's / owner's notifications + the `SlapHitAt` StealAlerts FX) and tells the attacker "You caught <name>! The slime went home."; a wild slime (or the hauled boss) lands where the victim stands (`ctx.positionOf`), the victim hears "You got bonked! You dropped the <slime>." and the attacker "You hit <name>! They dropped the slime." Returns the slime id, nil when the player carried nothing. **Every PvP item that hits a player calls it** (also when the target is immune to the item's control or slow): gloves (every tier, the punched player and every blast / chain victim), traps (every tier, also the players a Mega Trap pulls in), all three Goo Blasters (Squirter, Blaster, Cannon: a blob hit, a Cannon splash and anyone walking into a blaster pool or splat) and the Fun items that touch a player (§26.8: Goo Balloon splash, Bubble Wand bubble, Bounce Pad, Squeaky Hammer, Slime Hat Launcher hat, Dance Bomb disco). The Confetti Popper is cosmetic only and never catches; Goo Fireworks hits nobody.
- **Save:** `pvp = { tiers = { Knockback = tier?, Blaster = tier? }, traps = { [GooTrapN] = charges }, fun = { id } }` (`SaveData.cleanPvp`): missing / junk -> nothing owned, unknown ids ignored, numbers clamped (charges 0..`TRAP_MAX_HELD`). `SAVE_VERSION` 8: `SaveData.migrateV7` turns an owned trap tier (`tiers.Trap = n`) into `TRAP_MAX_HELD` charges of `GooTrap<n>` and drops `tiers.Trap`. Placed traps are never saved. `PlayerData.pvp` holds `fun` as a set.
- **Remote:** `Request("BuyPvpItem", id)`, rate limit 0.5 s (`Validate.ACTIONS`). Server checks flag, rank, cash and ownership (traps: the held cap); the toast is "<name> bought!".
- **`server/PvpService`:** one `PvpRules.State` per session (weak table, never saved), only with the flag on. After a use that spends the item's last trap charge the item is unequipped.
- **Walk speed (`server/PvpSlow`, pure):** the one per-session record of PvP holds and slows. `walkFactor(session, now)` is 0 while held, else the slow factor, else 1; `Carry.targetWalkSpeed` multiplies it in, so the existing `TargetWalkSpeed` enforcement applies and restores it by itself.
- **Fun items (`FunConfetti`..`FunFireworks`, `server/PvpFun`):** rules, events and the client look are in §26.8.

## 26.4 Knockback gloves (`KnockGlove1-5`, `server/PvpKnockback`, pure `Shared.PvpKnockbackRules`)

- `UsePvpItem(itemId, targetUserId, nil, charged?)`. The client fires a glove (and the Goo Cannon) on the release of the click / tap; a touch long press counts as held. Reach `tool.reach` (10) from the attacker's server position. A tap is a punch; `charged = true` (the client held the button at least `Config.PVP.CHARGE_SECONDS`) is a power punch: push x `CHARGE_PUSH` (1.5), cooldown x `CHARGE_COOLDOWN`. The server trusts the flag only for that trade (a longer cooldown for a longer push).
- Order: reach; a carrier drops their slime (`hitCarrier`, always, also when the push is refused); the push needs `PvpRules.canControl` (then `applyControl` for `KNOCKBACK_CONTROL_SECONDS`); neither caught nor pushed = refused "target is immune" (no cooldown). The push goes through `ctx.launch` along `PvpKnockbackRules.plan`: away from the attacker, `push` studs plus the row's `arc`, capped at `KNOCKBACK_MAX_PUSH` / `KNOCKBACK_ARC_HEIGHT`, landing clamped inside `MAP_BOUNDS` minus `KNOCKBACK_BOUNDS_MARGIN`; the void guard (`Rescue.shouldRescuePvp`) stays.
- Specials (`tool.special`): `"bonk"` (Bonk: a clean punch, clients pop a "BONK!"), `"bounce"` (Bounce: `pogo` = bounce heights, the victim's client bounces it that many times, each lower), `"boom"` (Boom: everyone else within `blastRadius` of the target is pushed `blastPush` away from it), `"thunder"` (Thunder: up to `chain` other players within `chainRange` of the target are pushed `push x chainFactor`), `"royal"` (Royal: a long push with a high `arc`, gold confetti). Every extra player hit by a blast or chain also drops any slime they carry and skips immune players.
- Events: `Effect { effect = "Knockback", attacker, target, itemId, special, charged, position, push, velocity, pogo?, duration }` for the punched player; a blast / chain victim gets its own `Knockback` effect with `from` = the punched player's position (`chained = true`).

## 26.5 Goo Traps (`GooTrap1-3`, `server/PvpTrap`, pure `Shared.PvpTrapRules`)

- **Charges:** buying a trap tier adds one charge (`data.pvp.traps[id]`), at most `TRAP_MAX_HELD` (5) per tier ("you can only hold 5"). The hotbar shows the stack count (`State.pvp.charges`).
- **Placing:** `UsePvpItem(itemId, nil, aim)` with the point under the click. The aim must be finite and within `TRAP_PLACE_RANGE` of the owner's server position; anywhere on the map. One charge is used. An owner has at most `TRAP_MAX_LIVE` (5) live traps over all tiers: placing a 6th removes the oldest (`TrapCleared`). A trap lives `TRAP_LIFETIME_SECONDS` (180) or until it catches someone. A trap is server-side data, not a Part.
- **Springing** (per-player tick, `PvpTrap.tick(world, session, position, now, ctx)`): any player except the owner, within `radius` (XZ, +-`PvpTrapRules.HEIGHT`). Puddle: slow `slow` for `slowSeconds` (goo on the feet). Sticky: held `control` s, then slowed `slow` for `slowSeconds`. Mega: held `control` s, everyone else within `pull` studs is pulled onto it and held too, and when the hold ends they are spat out with a small bounce (`spit`, `spitArc`). A carrier always drops their slime (`hitCarrier`). A player who is immune and carries nothing passes and the trap stays. A trap that caught someone is removed.
- **Events:** `TrapPlaced` / `TrapCleared` `{ owner, trapId, itemId, position }` to every client (cleared on catch, expiry, the 6th trap, owner leave, flag off). A player who joins gets a `TrapPlaced` with `replay = true` for every live trap, sent to them only (`PvpService.onJoin`); clients play no throw for a replay; `Effect { effect = "Freeze", attacker = owner, target, itemId, trapId, position, duration, hold }` per caught player (`hold` = held seconds, 0 for the Puddle); the Mega spit is an `Effect` `"Knockback"` with `itemId` of the trap.
- **Look (client):** every player sees every trap. The owner sees their traps glowing in goo green; everyone else sees them red (a glowing red disc, the trap model tinted red), so a trap is a visible danger. The marker is the `PvpModels` placeholder (`PvpModels.markerParts(itemId)`) on a goo disc of the trap's radius; once `PvpModels.markerMesh(itemId)` has an uploaded mesh the client shows that instead.

## 26.6 Goo Blasters (`GooBlaster1-3`, `server/PvpBlaster`, pure `Shared.PvpBlasterRules`)

- `UsePvpItem(itemId, targetUserId?, aim?)`. The server owns the shot: the blob leaves the attacker's server position and flies a ballistic arc (`PvpBlasterRules.arc`: gravity `BLOB_GRAVITY`, speed `tool.speed`, flight time from the distance) to the aim point (or the target's server position), clamped to `tool.range`. The hit is the first player (not the attacker) within `HIT_RADIUS` of the arc at fire time. The client only sends the aim; range, aim and rate are checked on the server.
- Squirter (`shots` 6, `shotGap`): rapid fire; the cooldown (`cooldown`, the refill) starts after the 6th shot of a tank. A hit stacks `slow` per hit up to `slowMax` and adds `slowSeconds`, the whole slow capped at `SLOW_MAX_SECONDS` from its first hit (`PvpRules.extendSlow`), then immunity. A hit catches a thief.
- Blaster (`blobs` 3, `spreadDeg`): three blobs in a fan; each blob hits at most one player, a player at most once per shot; a hit slows and catches a thief.
- Cannon (`splash`, `pool`, `poolSeconds`): a big lob; on impact everyone within `splash` studs is slowed and thieves are caught; a slowing pool stays `poolSeconds`.
- A blob that hits nobody leaves a slippery splat (`SPLAT_RADIUS`, `SPLAT_SECONDS`, slow `SPLAT_SLOW` for `SPLAT_SLOW_SECONDS`) at its end point; a pool / splat slows players who walk in (not the shooter, respecting immunity) and catches a thief who walks in (immune or not). At most `SPLAT_MAX` per shooter (the oldest goes).
- Events: one `Effect { effect = "Slow", attacker, target?, itemId, from, position, flight, duration, splat?, splash? }` per blob (`from` = muzzle, `position` = impact, `flight` = seconds in the air; `splat = { radius, seconds }` when a ground splat / pool is left). A splash / pool / splat victim gets an `Effect "Slow"` without `from`. The victim's client splats goo on the edge of its screen and tints the character green.

## 26.2 The default Bat (LIVE for everyone, NOT behind `FEATURES.PvP`)

- The on-screen Slap button and the `"Slap"` Request action are gone. Every spawn gives exactly one `Tool` named `Bat` (`server/BatTool.give`, Backpack, `CanBeDropped = false`, one inert Handle part). `Tool.Activated` (tap / click) fires on the server: **no remote, the client names no target.**
- `BatTool.swing` uses the swinger's own root position and look vector (`Shared.BatRules.pickTarget`): the nearest player carrying a slime (stolen or wild) within `SLAP_REACH` and in front (`Config.BAT.FACING_DOT`; closer than `CLOSE_STUDS` any direction). It then calls `CarryDrop.slap` (the same rules as the old button: reach, `SLAP_COOLDOWN` via `Session.lastSlapAt`; a stolen slime drops and bounces home with its notifications + `SlapHitAt` FX, a wild one drops at the carrier's feet) and adds a knockback of `Config.BAT.PUSH` studs through `PvpKnockbackRules.plan` + `PvpLaunch`, announced with `PvpEvent` `Effect` `Knockback` (`itemId "Bat"`; `PvpEffects` starts with the flag off too). With the flag on the target's control immunity (`PvpRules.canControl`) is respected.
- With the flag on, a non-thief anywhere on the map is pushed (no damage, no safe zones).
- A swing at nothing or at a non-thief does nothing else (no damage, no cooldown; swings are rate limited to `BAT.SWING_GAP`). Humanoid health is never touched.
- **The swing look:** every click (hit or miss, at most once per `BAT.SWING_GAP`) sets the Player attribute `BatSwingAt` (`Constants.BAT_SWING_ATTRIBUTE`, server time of the swing) and plays the handle's `Swing` sound (`BatModel.SWING_SOUND`). Every client plays the procedural swing (§26.3) when the attribute changes; the swinger's own client plays it at once on `Tool.Activated`. No `toolanim` value, no uploaded animation. Hit feedback stays the `Knockback` FX and the `SlapHitAt` bonk.
- **Model / icon / sound hookup is `Shared.BatModel` only** (`MESH_ID`, `ICON_ID`, `SIZE`, `GRIP`, `SWING_SOUND`).

## 26.1 PvP remote contract (final names; the client builds against this)

Everything is behind `Config.FEATURES.PvP` (default `true`). With the flag off the server refuses every PvP action with "PvP is not open yet", sends no `State.pvp`, fires no `PvpEvent` and sets no PvP attributes. Times are **server time** (`workspace:GetServerTimeNow()`); the client compares against the same clock.

**Where things live**
- Remote names: `src/shared/Constants.luau` (`REQUEST` = `"Request"`, `STATE` = `"State"`, `PVP_EVENT` = `"PvpEvent"`); remote definitions and argument types: `src/shared/Remotes.luau` (`Remotes.DEFINITIONS`, `Remotes.ACTIONS`), all under `ReplicatedStorage.Remotes`.
- Item data the client reads: `Config.PVP_TOOLS` (`src/shared/Config.luau`), keyed by item id. Each entry: `id` (save key, never renamed), `name`, `line` (`"Knockback" | "Trap" | "Blaster" | "Fun"`), `tier` (1..n within the line; Fun items are tier 1), `rebirths` (the rank gate, always a `Config.REBIRTH_TIERS` threshold), `cooldown` (s), `kind` (`"tool" | "fun"`), `cosmetic` (bool), effect params (§26.4-26.6). Per-rank unlocks = filter `PVP_TOOLS` by `rebirths <= player rebirths`. Prices: `Shared.PvpRules.price(id)` (pure; the client may require it).

**Client -> server** (all through the existing `Request` RemoteFunction: `Request:InvokeServer(action, ...)`, returns `(ok: boolean, message: string?)` like every other action)

| Action | Args | Notes |
|---|---|---|
| `BuyPvpItem` | `itemId: string` | Cash only. Checks flag, rank, cash, already owned / the trap held cap. A higher glove / blaster tier supersedes the lower ones of its line; a trap buy adds one charge. |
| `EquipPvpItem` | `itemId: string?` | Owned item into the hand slot; `nil` unequips. Only one equipped item. Equipping adds only the held model (§26.3) to the character. |
| `UsePvpItem` | `itemId: string, targetUserId: number?, aim: Vector3?, charged: boolean?` | Must be the equipped item. `targetUserId` for targeted items (gloves); `aim` = world point for aimed / placed items (Blaster, Goo Trap, every Fun item, §26.8); `charged` = the client held the button at least `Config.PVP.CHARGE_SECONDS` (a glove's power punch §26.4, the Confetti Popper's mega pop and the Goo Fireworks volley §26.8; ignored by every other item). The server validates reach, range, cooldown; a refused use returns `false, reason` and starts no cooldown. |

Rate limits: `BuyPvpItem` / `EquipPvpItem` 0.5 s, `UsePvpItem` 0.2 s (`Validate.ACTIONS`); the per-item cooldown is separate and server-authoritative.

**Server -> client**

1. **Snapshot** in the existing `State` event, field `pvp` (present only with the flag on):
   `pvp = { rank = number (rebirths), owned = { [itemId]: true }, best = { Knockback = itemId?, Trap = itemId?, Blaster = itemId? }, equipped = itemId?, cooldowns = { [itemId]: endsAt }, charges = { [trapItemId]: number } }`.
   Sent on join, on `Sync`, and after every Buy / Equip / Use.
2. **`PvpEvent`** RemoteEvent (ServerToClient). One table argument with a `kind`; all carry `serverTime`.

| kind | Fields | Sent to |
|---|---|---|
| `"Cooldown"` | `itemId, duration, startedAt` | the user |
| `"Effect"` | `attacker: number (userId), target: number? (userId), itemId, effect` (`"Knockback" | "Freeze" | "Slow"`, and the Fun effects of §26.8 with their own fields), `position: Vector3?, duration: number?, push: number?, velocity: {X, Y, Z}?` plus the per-line fields of §26.4-26.6 | every client (FX only; clients may skip it beyond their stream radius). `velocity` (Knockback, the Fun `Bounce` incl. the owner's own Bounce Pad launch, the Fun `Boing`) = the launch the server planned (`PvpKnockbackRules.velocity`); the **victim's own client** applies it to its HumanoidRootPart after `PvpKnockbackRules.clampVelocity` (a real player's character is network-owned) |
| `"TrapPlaced"` / `"TrapCleared"` | `owner: number, trapId: string, itemId, position: Vector3`, `replay: true?` (a live trap re-sent to a player who joined) | every client; a replay only to the joiner |

Player attributes (replicated, read-only hints for other players' UI): `PvpEquipped` (string item id; nil = none).

**Runtime parts (hard constraint: zero net parts at rest).** Nothing PvP-related exists in Workspace while the flag is off or while nobody has an item equipped and nothing is placed. The exceptions are the held model of an equipped item (§26.3), the client-only markers of placed traps / Bounce Pads (removed on `TrapCleared`) and the client-only flat goo splat / pool a Goo Blaster blob leaves (gone after its seconds). Use effects (particles, beams, the flying goo blob as a single particle, popups) are transient and destroyed within their plan's seconds. The server creates no Part for a trap, a blob, a splat, a pool or a Bounce Pad; its one use part is the Bubble Wand's bubble around a lifted player (§26.8: one collision-free ball, destroyed within the tool's `control` seconds). `RuntimeParts.spec` checks that a PvP-on server at rest adds 0 parts and that a use leaves 0 parts after cleanup.

## 26.3 Held models and use animations

- **Held model (server, `server/PvpHeld`, flag on only).** While a player has a PvP item equipped (`PvpEquipped`) and is not carrying, the server keeps one Model `PvpHeld` (`PvpModels.MODEL_NAME`) under the character, welded to the right hand's `RightGripAttachment` with the item's `GRIP` (the same convention as `Tool.Grip`). Every part is `CanCollide` / `CanQuery` / `CanTouch` false, `Massless`, no shadow. It is rebuilt when the item changes and destroyed on unequip, carry, respawn, leave and flag off. Not a Tool: the hotbar's one-hand rule stays as §29 says (a Tool and a PvP item never share the hand).
- **Look registry: `Shared.PvpModels` only** (pattern of `Shared.BatModel`). Every `Config.PVP_TOOLS` id has `mesh` (a `MeshAssets` name: `pvp_knock_glove_1..5`, `pvp_goo_trap_1..3`, `pvp_goo_blaster_1..3`, `pvp_fun_confetti`, `pvp_fun_balloon`, `pvp_fun_bubbles`, `pvp_fun_bounce_pad`, `pvp_fun_squeaky`, `pvp_fun_hat_launcher`, `pvp_fun_dance_bomb`, `pvp_fun_fireworks`), `size` (studs: the mesh's native size from `MeshAssets`, the mesh is fitted to it; a placed marker uses it too), optional `held` (one uniform scale of the mesh in the hand only, default 1: the Goo Traps and the Bounce Pad are smaller in the hand than on the ground), `grip` (`pos` studs in the mesh's own axes from its bbox centre, scaled with `held`, and `rotDeg`; it places the mesh only, the placeholder pieces sit on the bare `RightGripAttachment`) and `pieces` (the placeholder: a few Parts in the item's colours). The names are in `MeshAssets.NAMES` without entries until uploaded; while `MeshAssets.meshId(mesh)` is nil the placeholder pieces are used, once it is set the server builds one MeshPart (`CreateMeshPartAsync`, cached per mesh) and falls back to the pieces if that fails. Hooking up an uploaded mesh is one `MeshAssets` entry. A placed Goo Trap / Bounce Pad marker uses the same hook (`PvpModels.markerMesh(itemId)`): with the flag on the server publishes one MeshPart template per marker mesh (native size) in `ReplicatedStorage.PvpMarkerMeshes` (`Constants.PVP_MARKER_MESHES`, `MeshSwap.publishPvpMarkerTemplates`), because a script-made FileMesh draws white; the client clones it, and uses the placeholder pieces while it is missing. The trap model keeps its own colours and is solid for the owner, who also sees the glowing goo disc around it; everyone else sees a glowing red disc and the model tinted red.
- **Use animations (client, `ui/PvpAnim` + pure `ui/PvpAnimLogic`).** Procedural poses on the R15 joints (the `Transform` of each `Motor6D`, or `AnimationConstraint` on avatars with Roblox's joint upgrade, written in `RunService.Stepped` after the Animator so they ride on top of the walk / idle; R6 and missing joints are skipped), no animation asset. Kinds: `swing` (Bat), `punch` (Knockback), `blast` (Blaster: aim + recoil), `throw` (Trap, Bounce Pad, Balloon, Fireworks: under-arm throw / place), `use` (other fun items: a raised flourish), `hit` (the victim of a Knockback / Bounce / Squeaky nudge: recoil) and the `hold` pose (arm forward) while `PvpEquipped` is set. Culled by distance (`PvpAnimLogic.RANGE`) and only stepped while something is playing or held in range.
- **Replication without a new remote.** The local player's own use plays at once on the click (Inventory) and its own Bat swing on `Tool.Activated`; everyone else's comes from data that already replicates: PvpEvent `Effect` (`attacker` plays its line's use, the `target` of a push plays `hit`), `TrapPlaced` (the `owner` plays `throw`), Player attribute `BatSwingAt` (the swinger plays `swing`) and `PvpEquipped` (the hold pose). A refused use is not announced, so only the user's own client shows its whiff.
- **Hit feel (client FX, `ui/PvpEffects`, same caps).** Knockback: a white impact flash that settles into the tier colour, a ring burst and the victim's `hit` recoil, plus the glove's special (BONK! popup, pogo bounces, blast ring, lightning to the chained players, gold confetti). Freeze: goo at the victim's feet (Mega: jaws snap). Slow: the goo blob flies its arc as one particle, then splats on the target (goo on the edge of the victim's screen, a green tint) or on the ground. All built-in instances, transient, counted by `activeCount()`.

## 26.8 Fun items (`FunConfetti`..`FunFireworks`, `server/PvpFun`)

Silly, mostly cosmetic toys. Data: the Fun rows of `Config.PVP_TOOLS` (`cooldown`, `cosmetic`, `control`, `slow` / `slowSeconds`, `reach`, `nudge`, `height`, `maxPlaced`, `hatSeconds`) and every other tunable in `Config.PVP_FUN` (one sub-table per item, plus `AIM_RANGE` and the client caps). Pure geometry shared by server and client (flight times, bubble paths, the hat shot, combo counting, the fireworks colour): `Shared.PvpFunRules`.

**Rules (all items)**
- Every item is used with `UsePvpItem(itemId, nil, aim, charged?)`. A `targetUserId` is refused ("no target needed"), so `PvpService.use`'s plot / thief rule never applies: the handler picks who is hit. A missing `aim` falls back to a point in front of the user (`ctx.pose`); an `aim` beyond the item's range is pulled in along the same direction, never refused.
- Who is affected: players with a character (`ctx.positionOf`) in the item's area. The user is never hit by their own control, slow or lift. Control goes through `PvpRules.applyControl` (<= `CONTROL_MAX_SECONDS`, then `CONTROL_IMMUNITY_SECONDS`): an immune player gets the cosmetic part only.
- **Hit carrier:** every Fun item that touches another player carrying a slime makes them drop it through `PvpService.hitCarrier` (§26: a stolen slime goes home, a wild one lands at their feet; one toast for the user), immunity or not: the Goo Balloon splash, a Bubble Wand bubble, a Bounce Pad bounce, a Squeaky Hammer bonk, a Slime Hat Launcher hat and the Dance Bomb disco. The Confetti Popper is purely cosmetic: its rain never knocks a slime loose and never controls or slows anyone. Goo Fireworks touches nobody. The user never catches themself.
- Control holds (`PvpFun.frozen`: walk speed 0 through the `TargetWalkSpeed` enforcement in `WorldView.updatePlayer`) and the Balloon slow (`PvpFun.walkFactor`, multiplied into `Carry.targetWalkSpeed`) end by themselves. Everything the server keeps (thrown items in flight, bubble streams, pads, discos, holds, hat stacks, hammer combos) is runtime data with a lifetime and a cap, never saved, dropped on leave / flag off (`PvpService.onCleanup`), and stepped in the per-player `WorldView.updatePlayer` tick (`PvpFun.tick`; no loop of its own).
- No fun item lowers health or changes a slime's owner, value or data.

**Items** (`Config.PVP_FUN` names; Effects are `PvpEvent` `Effect` with `attacker`, `itemId`, `effect` and the fields listed)

| Item | Use | Server, Effects |
|---|---|---|
| Confetti Popper | aim anywhere, also straight up; `charged` = mega pop | Burst `CONFETTI.RANGE` studs along the aim; everyone within `RADIUS` (mega `MEGA_RADIUS`) of it gets confetti stuck for `STICK_SECONDS` (cosmetic only). Never catches a thief, never controls. `Confetti { position, radius, targets = { userId }, mega }`. |
| Goo Balloon | thrown in an arc to `aim` (<= `AIM_RANGE`) | Lands after `PvpFunRules.flightTime`; everyone within `BALLOON.SPLASH_RADIUS` at landing is painted for `PAINT_SECONDS` (cosmetic); a thief is also slowed by the tool's `slow` for `slowSeconds` (`applySlow`). Thief -> slime home. `Balloon { origin, position, landAt }`, then `Paint { target, duration, slowed }` per player. |
| Bubble Wand | a stream of `BUBBLES.COUNT` bubbles toward `aim` | Paths are `PvpFunRules.bubbleAt` (straight, rising, `LIFETIME`). A player a bubble touches (`RADIUS`) is lifted `LIFT` studs in a bubble for the tool's `control` seconds (`ctx.funBubble`: one collision-free ball welded to the root, an AlignPosition and a ClickDetector; any other player within `POP_RANGE` may click it to pop it early, `PvpFun.pop`). **Client** (`ui/PvpFunFx` + pure `ui/PvpFunFxLogic`, handed every Fun event by `ui/PvpEffects`): built-in instances only, all transient and counted (`PvpFunFx.activeCount()`, 0 when idle; at most `PVP_FUN.FX_MAX` effects and `PROXIES_MAX` squash / float proxies at once). Slime and pancake squashes use a local proxy (a stripped clone with the originals hidden through `LocalTransparencyModifier`), so slime models, their rigs and VisualsClient are never touched. Motion is tweens and client-only physics, plus the existing 10 Hz client tick (`PvpFunFx.tick`) for bubble / pad checks against wild slimes; no new per-frame loop. Poses come from `ui/PvpAnim` (`pop`, `blow`, `bonk`, `throw`, `blast` for the user; `dance` and `flip` on the affected player). Hold to charge: the Confetti Popper and Goo Fireworks fire on the release of the click / tap and send `charged = true` when held at least `Config.PVP.CHARGE_SECONDS` (a touch long press counts as held), like the gloves.
