## 26.1 PvP remote contract (final names; the client builds against this)

Everything is behind `Config.FEATURES.PvP` (default `true`). With the flag off the server refuses every PvP action with "PvP is not open yet", sends no `State.pvp`, fires no `PvpEvent` and sets no PvP attributes. Times are **server time** (`workspace:GetServerTimeNow()`); the client compares against the same clock.

**Where things live**
- Remote names: `src/shared/Constants.luau` (`REQUEST` = `"Request"`, `STATE` = `"State"`, new `PVP_EVENT` = `"PvpEvent"`); remote definitions and argument types: `src/shared/Remotes.luau` (`Remotes.DEFINITIONS`, `Remotes.ACTIONS`), all under `ReplicatedStorage.Remotes`.
- Item data the client reads: `Config.PVP_TOOLS` (`src/shared/Config.luau`), keyed by item id. Each entry: `id` (save key, never renamed), `name`, `line` (`"Knockback" | "Trap" | "Blaster" | "Fun"`), `tier` (1..n within the line; Fun items are tier 1), `rebirths` (the rank gate, always a `Config.REBIRTH_TIERS` threshold; the rank title is the `REBIRTH_TIERS` entry with that `rebirths`), `cooldown` (s), `kind` (`"tool" | "fun"`), `cosmetic` (bool), effect params, exact Config field names: gloves `push`, `reach`; traps `traps` (max armed), `control` (freeze s), `radius`, re-arm = `cooldown`; blasters `slow` (fraction 0..1, e.g. 0.3 = 30 %), `slowSeconds`, `range`; fun items per entry). Per-rank unlocks = filter `PVP_TOOLS` by `rebirths <= player rebirths`. Prices: `Shared.PvpRules.price(id)` (pure; the client may require it). Rules the client may mirror for UI hints only (server decides): `Shared.PvpRules.inSafeZone`, `bestTool`, `isUnlocked`.

**Client -> server** (all through the existing `Request` RemoteFunction: `Request:InvokeServer(action, ...)`, returns `(ok: boolean, message: string?)` like every other action)

| Action | Args | Notes |
|---|---|---|
| `BuyPvpItem` | `itemId: string` | Cash only. Checks flag, rank, cash, already owned. A higher tier supersedes the lower ones of its line. |
| `EquipPvpItem` | `itemId: string?` | Owned item into the hand slot; `nil` unequips. Only one equipped item. Equipping adds only the held model (§26.3) to the character. |
| `UsePvpItem` | `itemId: string, targetUserId: number?, aim: Vector3?, power: number?` | Must be the equipped item. `targetUserId` for targeted items (gloves); `aim` = world point for aimed / placed items (Blaster, Goo Trap, every Fun item, §26.4); `power` = the hold charge 0..1 (Confetti mega pop, Fireworks volley; clamped, junk = 0). The server validates reach, cooldown, safe zones, shield, own-plot / thief rule; a refused use returns `false, reason` and starts no cooldown. |

Rate limits: `BuyPvpItem` / `EquipPvpItem` 0.5 s, `UsePvpItem` 0.2 s (`Validate.ACTIONS`); the per-item cooldown is separate and server-authoritative.

## 26.3 Held models and use animations

- **Held model (server, `server/PvpHeld`, flag on only).** While a player has a PvP item equipped (`PvpEquipped`) and is not carrying, the server keeps one Model `PvpHeld` (`PvpModels.MODEL_NAME`) under the character, welded to the right hand's `RightGripAttachment` with the item's `GRIP` (the same convention as `Tool.Grip`). Every part is `CanCollide` / `CanQuery` / `CanTouch` false, `Massless`, no shadow. It is rebuilt when the item changes and destroyed on unequip, carry, respawn, leave and flag off. Not a Tool: the hotbar's one-hand rule stays as §29 says (a Tool and a PvP item never share the hand).
- **Look registry: `Shared.PvpModels` only** (pattern of `Shared.BatModel`). Every `Config.PVP_TOOLS` id has `mesh` (a `MeshAssets` name: `pvp_knock_glove_1..5`, `pvp_goo_trap_1..3`, `pvp_goo_blaster_1..3`, `pvp_fun_confetti`, `pvp_fun_balloon`, `pvp_fun_bubbles`, `pvp_fun_bounce_pad`, `pvp_fun_squeaky`, `pvp_fun_hat_launcher`, `pvp_fun_dance_bomb`, `pvp_fun_fireworks`), `size` (studs, the mesh is fitted to it), `grip` (`pos` studs, `rotDeg`) and `pieces` (the placeholder: a few Parts in the item's colours). The names are in `MeshAssets.NAMES` without entries until uploaded; while `MeshAssets.meshId(mesh)` is nil the placeholder pieces are used, once it is set the server builds one MeshPart (`CreateMeshPartAsync`, cached per mesh) and falls back to the pieces if that fails. Hooking up an uploaded mesh is one `MeshAssets` entry. A placed Goo Trap / Bounce Pad marker may use the same mesh later (`PvpModels.markerMesh(itemId)`); today the marker stays the flat client disc.
- **Use animations (client, `ui/PvpAnim` + pure `ui/PvpAnimLogic`).** Procedural poses on the R15 joints (the `Transform` of each `Motor6D`, or `AnimationConstraint` on avatars with Roblox's joint upgrade, written in `RunService.Stepped` after the Animator so they ride on top of the walk / idle; R6 and missing joints are skipped), no animation asset. Kinds: `swing` (Bat), `punch` (Knockback), `blast` (Blaster: aim + recoil), `throw` (Trap, Bounce Pad, Balloon, Fireworks: under-arm throw / place), `use` (other fun items: a raised flourish), `hit` (the victim of a Knockback / Bounce / Squeaky nudge: recoil) and the `hold` pose (arm forward) while `PvpEquipped` is set. Culled by distance (`PvpAnimLogic.RANGE`) and only stepped while something is playing or held in range.
- **Replication without a new remote.** The local player's own use plays at once on the click (Inventory) and its own Bat swing on `Tool.Activated`; everyone else's comes from data that already replicates: PvpEvent `Effect` (`attacker` plays its line's use, the `target` of a push plays `hit`), `TrapPlaced` (the `owner` plays `throw`), Player attribute `BatSwingAt` (the swinger plays `swing`) and `PvpEquipped` (the hold pose). A refused use is not announced, so only the user's own client shows its whiff.
- **Hit feel (client FX, `ui/PvpEffects`, same caps).** Knockback: a white impact flash that settles into the tier colour, a ring burst and the victim's `hit` recoil. Freeze: a goo splash ring at the victim's feet. Slow: a goo beam from the attacker's hand and a splat on the target. All built-in instances, transient, counted by `activeCount()`.

## 26.4 Fun items (`FunConfetti`..`FunFireworks`, `server/PvpFun`)

Silly, mostly cosmetic toys. Data: the Fun rows of `Config.PVP_TOOLS` (`cooldown`, `cosmetic`, `control`, `slow` / `slowSeconds`, `reach`, `nudge`, `height`, `maxPlaced`, `hatSeconds`) and every other tunable in `Config.PVP_FUN` (one sub-table per item, plus `AIM_RANGE`, `CHARGE_SECONDS`, the client caps). Pure geometry shared by server and client (flight times, bubble paths, the hat shot, combo counting, the fireworks colour): `Shared.PvpFunRules`.

**Rules (all items)**
- Every item is used with `UsePvpItem(itemId, nil, aim, power?)`. A `targetUserId` is refused ("no target needed"), so `PvpService.use`'s plot / thief rule never applies: the handler picks who is hit. A missing `aim` falls back to a point in front of the user (`ctx.pose`); an `aim` beyond the item's range is pulled in along the same direction, never refused.
- Who is affected: players with a character (`ctx.positionOf`) in the item's area. The user is never hit by their own control, slow or lift. **Shielded players** (new-player shield) get only the cosmetic part (confetti, paint, hats, fireworks); every control, slow, launch and lift skips them. Control goes through `PvpRules.applyControl` (<= `CONTROL_MAX_SECONDS`, then `CONTROL_IMMUNITY_SECONDS`): an immune player gets the cosmetic part only. Fun items do not read safe zones.
- **Caught thief:** when a Bubble lifts, a Bounce Pad launches, a Squeaky Hammer bonks or a Dance Bomb makes dance a player carrying a stolen slime, the slime goes home through `StealService.escape(..., "slap")` (drop + bounce home + both toasts) plus a toast for the catcher (`PvpFun.sendSlimeHome`), immunity or not.
- Control holds (`PvpFun.frozen`: walk speed 0 through the `TargetWalkSpeed` enforcement in `WorldView.updatePlayer`) and the Balloon slow (`PvpFun.walkFactor`, multiplied into `Carry.targetWalkSpeed`) end by themselves. Everything the server keeps (thrown items in flight, bubble streams, pads, discos, holds, hat stacks, hammer combos) is runtime data with a lifetime and a cap, never saved, dropped on leave / flag off (`PvpService.onCleanup`), and stepped in the per-player `WorldView.updatePlayer` tick (`PvpFun.tick`; no loop of its own).
- No fun item lowers health or changes a slime's owner, value or data.

**Client** (`ui/PvpFunFx` + pure `ui/PvpFunFxLogic`, handed every Fun event by `ui/PvpEffects`): built-in instances only, all transient and counted (`PvpFunFx.activeCount()`, 0 when idle; at most `PVP_FUN.FX_MAX` effects and `PROXIES_MAX` squash / float proxies at once). Slime and pancake squashes use a local proxy (a stripped clone with the originals hidden through `LocalTransparencyModifier`), so slime models, their rigs and VisualsClient are never touched. Motion is tweens and client-only physics, plus the existing 10 Hz client tick (`PvpFunFx.tick`) for bubble / pad checks against wild slimes; no new per-frame loop. Poses come from `ui/PvpAnim` (`pop`, `blow`, `bonk`, `throw`, `blast` for the user; `dance` and `flip` on the affected player). Hold to charge: the Confetti Popper and Goo Fireworks send `power` = held seconds / `CHARGE_SECONDS` on release (mouse) or after a long press (touch).
