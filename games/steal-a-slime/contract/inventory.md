# 29. Inventory hotbar and panel (S3, 2026-10-18)

**Status:** the hotbar itself is client-only. Consumable stacks (Merijn, 2026-10-18) add `State.consumables.held`, the saved stack and the `UseConsumable` action (restocking-shop.md); the server stays the only owner of what is held and validates every use.

- **Replaces** Roblox's backpack bar (`StarterGui:SetCoreGuiEnabled(Backpack, false)`, retried until the core scripts register).
- **List** (`src/ui/InventoryCore`, pure): the Bat first (the Tool every player gets, `BatTool`), then any other Tool in the Backpack / character by name (the Speed Coil while it is a Tool), then every owned PvP item (`State.pvp.owned`) in `Config.PVP_TOOLS` order, then every consumable with a stack (`State.consumables.held`, `Config.CONSUMABLES` order). The Speed Coil is an item (Item Shop): while owned it is a Tool in the Backpack and so has its own slot and panel cell. Permanent upgrades and the Lock are never listed. Pictures come from the ItemIcons registry (`Pvp_<id>` through `ItemIcons.shopIconId`, a Tool by its own id, the Bat through `ItemIcons.HELD_TOOLS`); an unknown Tool gets the neutral tile.
- **Equip / use:** selecting a Tool equips or unequips it through the Humanoid (what the default backpack did); selecting a PvP item sends the existing `Request("EquipPvpItem", id?)` (no id = put away). One hand: selecting a Tool puts an equipped PvP item away first, selecting a PvP item unequips the Tools. With a PvP item equipped, a click / tap on the world sends `Request("UsePvpItem", id, targetUserId?, aim?)` (`InventoryCore.pvpUseRequest`: gloves and the Dance Bomb target the clicked or nearest player in reach, thieves first; blasters, traps and placed items aim at the clicked point; Confetti / Bubbles send no arguments). A refusal (cooldown, safe zone, out of reach) shows as a short tip above the item's slot. A click that passes the client checks (the item's cooldown from `State.pvp.cooldowns`, `Inventory.USE_GAP`) plays the item's use animation on the player's own character at once (§26.3), whatever the server answers.
- **Consumables in hand:** the number key (1-9) or a tap puts the consumable in that slot in the hand, exactly as for a Tool; the same press again puts it away. "In hand" is client-side (the server has no hand slot for a consumable): it is dropped when a Tool or PvP item is picked, when carrying starts, or when the stack runs out. One hand: picking it puts the Tool / PvP item away first. While it is in hand, a click or tap on the world (a press no GUI took) sends `Request("UseConsumable", id, slimeId?)`, at most once per 0.5 s. The server validates the item and the stack, runs the existing effect and decrements the stack by one.
- **Hotbar:** bottom-centre zone `Layout.screen(...).hotbar` (between the money and status clusters, above them on a narrow portrait phone, hugging the bottom edge on a short landscape phone), at most 9 item slots plus the bag cell (`InventoryLayout`). Number keys 1-9 on keyboards, tap on touch (slot at least `Layout.MIN_TOUCH_DESIGN`), selected slot highlighted, name on hover or after a 0.4 s long press, cooldown seconds from `State.pvp.cooldowns`, the stack count of a consumable. Hidden while carrying (the server unequips tools then; the carry cards may use its place) and while a menu card is open. Items that do not fit a narrow phone's bar are in the panel.
- **Panel:** the bag cell opens the `Inventory` card (`Layout.MENU_HEIGHTS.Inventory`, same `Widgets.panel` chrome and `Layout.panelFor` rect as every menu) with a grid of everything held; tapping a cell equips it and closes the card.
- **Layout:** `Layout.screen` gains `hotbar`; only the plain tutorial card rises above the bar (`tutorialLift`), the carry card and the carrying tutorial keep their places. `LayoutAssert.hotbarChecks` runs in `standard` at every gate size.
