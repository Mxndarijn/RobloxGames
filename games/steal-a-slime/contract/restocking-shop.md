# 22. v29 #13: restocking consumables shop (2026-10-16; stacks 2026-10-18)

**Status:** `Config.FEATURES.Consumables` (default on); `false` = no Shop section, `BuyConsumable` refused ("the shop is closed"). Server-authoritative.

- **Schedule (`shared/Consumables`):** slot = `floor(unix time / CONSUMABLES_RESTOCK_SECONDS)` (300 s). The stock of a slot is a pure function of the slot (seeded `Rng`), so every server agrees; `State.consumables.restockAt` drives the shop countdown. Each item rolls `minStock..maxStock` = the quantity **each player** may buy this restock (0 = sold out); counts live in `data.consumables = { slot, bought, held }`; `slot` and `bought` reset when the slot changes, `held` never does.
- **Stacks (S3, Merijn 2026-10-18):** consumables are **held**. Buying adds one to `data.consumables.held[itemId]` (at most `CONSUMABLE_HELD_MAX` = 99 of an item; past it the purchase is refused, nothing charged) and applies nothing. Using one (`UseConsumable`) runs the effect and takes one off the stack.
- **Remote (buy):** `Request("BuyConsumable", itemId, slimeId?)`, rate limit 0.5 s (`Validate.ACTIONS`). Checks stock, cash (price x rebirth multiplier) and the held cap; `slimeId` is accepted for old clients and ignored.
- **Remote (use):** `Request("UseConsumable", itemId, slimeId?)`, rate limit 0.5 s. The server validates the feature flag, the item id and that the player holds at least one, then runs the **existing effect code unchanged** (`server/ConsumableShop`): `MutationSpray` needs `slimeId` (an owned, idle slime), `LuckPotion` extends `world.potionUntil` (refused at the cap), `WeatherTotem` calls the current restock slot's weather through the Weather service. The stack is decremented only after the effect succeeded, so a refusal ("pick a slime", "not your slime", "slime is busy", "the luck potion is already at its longest", ...) keeps it. Failures: `"you don't have any"`, `"unknown item"`.
- **Items (ids are save keys, never rename):** `MutationSpray` (rolls a `MUTATIONS` mutation onto an owned, idle slime; respects `MutationStacking` combos and `MAX_MUTATIONS`; rerolls a no-op roll up to 8 times), `LuckPotion` (server-wide: `world.potionUntil`, each potion adds `LUCK_POTION_SECONDS` up to `LUCK_POTION_MAX_SECONDS`; spawn luck = day/night modifier x `LUCK_POTION_MULT`, capped at `SPAWN_LUCK_CAP`, a modifier above the cap alone is never cut), `WeatherTotem` (`WeatherService.request`: the stock-seeded weather is next; only offered with `FEATURES.Weather` and a Weather service).
- **Save:** optional `consumables` field `{ slot, bought, held }`, default "nothing bought, nothing held"; no `SAVE_VERSION` bump. **Migration:** a save written before stacks has no `held` and loads with an empty stack (those purchases were applied when bought, so nothing is lost; `slot` and `bought` are kept exactly). `held` is read even when `bought` is damaged; per item it is floored and clamped to `0..CONSUMABLE_HELD_MAX`, unknown ids are dropped. **State:** `State.consumables?` (items with `left` / `max` / `held`, `restockAt`, `luckUntil`, and `held`: every item id with a stack, shown in the shop or not).
- **Hotbar / panel (client):** a consumable with a stack gets a slot after the Tools and PvP items, with the stack count; number key or tap puts it in hand (client-side selection, the same press again puts it away; one hand, so a Tool or PvP item is put away first); a click / tap in the world with it in hand sends `UseConsumable` (the spray's slime is the favourite, else the highest tier).
