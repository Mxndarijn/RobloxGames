# 43. Base shapes: the goo jar tower, the Goo Factory and the Mushroom Pagoda

**Status:** contract first. `Config.FEATURES.BaseShapes` (default **off** until the new bases have their meshes); `false` = no remote, no State fields, no plot attribute, every plot is the goo jar tower. The save field is still read and written.

**Design (2026-10-26, Merijn):** a plot's *base* is the building it stands in; its *skin* (§15) is the colour theme. They are chosen separately, so any base can wear any skin. The goo jar tower stays the default; the Goo Factory and the Mushroom Pagoda are rewards for rebirths. Every base keeps the same rules (§5.3): 4 floors of `PADS_PER_FLOOR` pads, floor f walks at `WorldLayout.floorTop(f)`, the only way in is the floor-1 door on the plot's -Z side, the merge vat and lock button stand inside on floor 1, players spawn at `WorldLayout.SPAWN_SPOT`, the owner leaves the top floor by an owner-only drop exit. Design pages: base concepts and the detailed Factory / Pagoda designs (kit `models/_factory_layout.py`, `models/_pagoda_layout.py`).

- **Rule:** `Config.PLOT_BASES` lists the bases: `{ id, name, rebirths? }`. A base unlocks once the owner's `data.rebirths >= rebirths` (no `rebirths` = always unlocked). `jar` (Goo Jar Tower, everyone), `factory` (Goo Factory, rebirth 20), `pagoda` (Mushroom Pagoda, rebirth 25). Ids are permanent save ids. `Config.PLOT_BASE_DEFAULT = "jar"`. `src/shared/PlotBases` (pure): `get`, `unlocked`, `current`, `equip`, `view`.
- **Save:** `plotBase: string` (`PlayerData`). Missing or unknown loads as `"jar"`; a locked base stays saved and shows as `jar` (`PlotBases.current`), so it comes back if rebirths ever allow it. No save version bump.
- **Remote:** `Request("EquipPlotBase", baseId)` (`string`; rate limit 0.5 s). Refused unless the flag is on and the base exists and is unlocked. Equipping `jar` always works.
- **State (flag on only):** `plotBase: string`, `plotBases: { { id, name, rebirths, unlocked, equipped } }` (jar first).
- **Plot attribute (flag on only):** `Plot_<i>.PlotBase = <id>` (`Constants.PLOT_BASE_ATTRIBUTE`; `"jar"` on a free plot). `WorldView.updatePlots` writes it **before** `BaseFloors.sync`.
- **Geometry:** `src/visuals/shared/BaseShapes` is the one place that knows each base: `BaseShapes.get(id)` returns the shape (`jar` wraps today's WorldLayout jar functions). Per shape: `padOffset(j)`, `padYaw(j)`, `inside(f, x, z)` (plot-local point inside floor f's walls), `floor1(i)` (the floor-1 nodes), `floor(i, f)` (an upper floor: `Floor_<f>` + its pads, like `WorldLayout.floor`), `top(i, f)` (the roof colliders, or nil when the roof is part of the floor), `dropLanding()`, `route` (`true` when the slime walk needs the hand-built `JarRoute` leg; other bases use pathfinding). Numbers for the new bases are generated from the kit layouts into `src/visuals/shared/BaseShapeData/<Name>.luau` (header says so; `tests/BaseShapes.spec` re-checks their rules: pad spacing, wall clearance, spawn, footprint, ramp width, slope and headroom).
- **Floor 1 is static as the jar** (`world/Plots.rbxmx`, `WorldLayout.build` unchanged). When a plot's `PlotBase` changes, the server (`server/BaseShapeSwap`) rebuilds floor 1 in place:
  1. anyone inside the plot is moved to the spawn spot; floors 2..4 are removed (prompts parked as today);
  2. the base's floor-1 pieces replace the other base's: everything under the plot except **kept** parts is destroyed, then the new base's `floor1(i)` nodes are built (`WorldBuilder.ensure`);
  3. **kept** parts keep their instance (and their prompts, meshes and client hooks) and are only moved and resized to the new base's node of the same name: `Base`, `PlotFloor`, `HomeZone`, `Slimes`, `Pad_1..8`, `MergeVat`, `LockButton` (with `Pedestal`), `Sign`, `LockSign`, `LockBarrier` (with `Stopper`);
  4. the new slots get their meshes (`MeshSwap.applyUnder`), every slime on a pad is placed again, and `BaseFloors.sync` builds the upper floors of the new base.
  Going back to the jar does the same with the jar's nodes from `WorldLayout.plot(i)`.
- **Upper floors and roof:** `BaseFloors` asks the plot's shape (`build`/`top` get the base). A shape may put its roof in the floor as "shown only while top" pieces (`JarFloor = f`, `JarShow = "top"`, `JarCollide` for colliders): the factory does; the jar keeps `TopColliders`.
- **Containment (one rule per base):** `Actions.insideJar`, `PlotLockGuard.insideJar` (and `SlimeGuardView`'s jar table) and `BaseFloors.evacuate` ask `BaseShapes.get(base).inside(f, x, z)`. The drop exit's owner check is unchanged otherwise (§5.3).
- **Lock:** `LockBarrier.Stopper` is the barrier in every base (moved and sized to the doorway). With no `StopperShut` look the primitive stopper shows while locked (today's fallback in `PlotDecor.applyLock`): the factory's roll-down shutter. `OpenDoorCollider` exists only where the door swings (jar, pagoda).
- **Skins on other bases:** a non-jar base's tint-only pieces are value-grey meshes whose slot carries `ThemeRole = <role>` (`MeshTint` stays the jar's lock-ring tint); `MeshSwap` sets `MeshPart.Color` to `BaseShapes.tint(base, skin, role)` when it places the mesh and on every skin change (verified in Studio: Color multiplies the vertex colours). A few pieces are themed meshes instead (`<piece>@<skin>`, up to 3 per skin per base; the factory: foot, roof kit, storey dressing), and a piece only some skins have appears and goes with the skin. The slot plan, boxes and tints are generated from the kit (`BaseShapeData/<Name>Meshes`, `models/_<name>_meshes.py`); the mesh entries are a generated MeshAssets block (`tools/base_mesh_assets.py`). Each collider names the mesh that is its look (`MeshStandIn`), so it hides once that mesh lands and shows as a primitive if it never does.
- **Client:** `PlotMascot` draws the jar mascot and ooze ring on `jar` plots only. The Skins menu gets a base row above the skins: each base with Equip / Equipped / "Rebirth N".
- **Studio-only debug (in-memory store only, `server/StudioHooks`):** player attribute `PcwPlotBase` (base id) raises that player's rebirths to the base's gate and equips it; with `PcwPads` the upper floors build. The flag itself is forced with `ReplicatedStorage.PcwFlag_BaseShapes = true` (`FeatureOverride`).
