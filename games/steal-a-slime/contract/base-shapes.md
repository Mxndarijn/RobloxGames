# 44. Base shapes: the goo jar tower, the Goo Factory and the Mushroom Pagoda

**Status:** live. `Config.FEATURES.BaseShapes` is **on** (the Factory and Pagoda meshes are uploaded); `false` = no remote, no State fields, no plot attribute, every plot is the goo jar tower. The save field is still read and written. The flag and its off path go one release after this ships.

**Design (2026-10-26, Merijn):** a plot's *base* is the building it stands in; its *skin* (§15) is the colour theme. They are chosen separately, so any base can wear any skin. The goo jar tower stays the default; every other base is an Exclusive, bought in the Exclusive Shop (the Goo Factory and the Mushroom Pagoda were rebirth rewards until save v13, Merijn 2026-10-29). Every base keeps the same rules (§5.3): 4 floors of `PADS_PER_FLOOR` pads, floor f walks at `WorldLayout.floorTop(f)`, the only way in is the floor-1 door on the plot's -Z side, the merge vat and lock button stand inside on floor 1, players spawn at `WorldLayout.SPAWN_SPOT`, the owner leaves the top floor by an owner-only drop exit. Design pages: base concepts and the detailed Factory / Pagoda designs (kit `models/_factory_layout.py`, `models/_pagoda_layout.py`).

- **Rule:** `Config.PLOT_BASES` lists the bases: `{ id, name, rebirths?, exclusive?, robux? }`. An `exclusive` base unlocks once owned (`ownedStyles.plotBase`, product `Base_<id>`); any other once `data.rebirths >= rebirths` (no `rebirths` = always unlocked). `jar` (Goo Jar Tower, everyone); `factory` (Goo Factory) and `pagoda` (Mushroom Pagoda) are Exclusive at 399 R$ like the five Exclusive bases. Save v13 (`SaveData.migrateV12`) gives a player whose rebirths had unlocked them (20 / 25, `SaveData.REBIRTH_BASES_V12`) ownership, once. Ids are permanent save ids. `Config.PLOT_BASE_DEFAULT = "jar"`. `src/shared/PlotBases` (pure): `get`, `unlocked`, `current`, `equip`, `view`.
- **Exclusive bases** (`exclusive = true`, priced in Robux by `robux`): `carousel` (Carousel Tent), `rocket` (Space Rocket), `treehouse` (Tree House), `lighthouse` (Lighthouse), `snowglobe` (Snow Globe). Each sells as the product `Base_<id>` (grant kind `plotBase`, `style = <id>`; also as the gift `Gift_Base_<id>`, contract/exclusive-shop.md §15). An Exclusive base is unlocked only while it is in `data.ownedStyles.plotBase`; rebirths never unlock it.
- **Save:** `plotBase: string` (`PlayerData`). Missing or unknown loads as `"jar"`; a locked base stays saved and shows as `jar` (`PlotBases.current`), so it comes back if rebirths ever allow it, or once an Exclusive base is owned again. Owned Exclusive bases: `ownedStyles.plotBase` (exclusive-shop.md §15). No save version bump.
- **Remote:** `Request("EquipPlotBase", baseId)` (`string`; rate limit 0.5 s). Refused unless the flag is on and the base exists and is unlocked. Equipping `jar` always works.
- **State (flag on only):** `plotBase: string`, `plotBases: { { id, name, rebirths, unlocked, equipped, exclusive?, productKey?, robux? } }` (jar first; `exclusive`, `productKey` = `"Base_<id>"` and `robux` on Exclusive bases only).
- **Plot attribute (flag on only):** `Plot_<i>.PlotBase = <id>` (`Constants.PLOT_BASE_ATTRIBUTE`; `"jar"` on a free plot). `WorldView.updatePlots` writes it **before** `BaseFloors.sync`.
- **Geometry:** `src/visuals/shared/BaseShapes` is the one place that knows each base: `BaseShapes.get(id)` returns the shape (`jar` wraps today's WorldLayout jar functions). Per shape: `padOffset(j)`, `padYaw(j)`, `inside(f, x, z)` (plot-local point inside floor f's walls), `floor1(i)` (the floor-1 nodes), `floor(i, f)` (an upper floor: `Floor_<f>` + its pads, like `WorldLayout.floor`), `top(i, f)` (the roof colliders, or nil when the roof is part of the floor), `dropLanding()`, `route` (`true` when the slime walk needs the hand-built `JarRoute` leg; other bases use pathfinding). Numbers for the new bases are generated from the kit layouts into `src/visuals/shared/BaseShapeData/<Name>.luau` (header says so; `tests/BaseShapes.spec` re-checks their rules: pad spacing, wall clearance, spawn, footprint, ramp width, slope and headroom).
- **Floor 1 is static as the jar** (`world/Plots.rbxmx`, `WorldLayout.build` unchanged). When a plot's `PlotBase` changes, the server (`server/BaseShapeSwap`) rebuilds floor 1 in place:
  1. anyone inside the plot is moved to the spawn spot; floors 2..4 are removed (prompts parked as today);
  2. the base's floor-1 pieces replace the other base's: everything under the plot except **kept** parts is destroyed, then the new base's `floor1(i)` nodes are built (`WorldBuilder.ensure`);
  3. **kept** parts keep their instance (and their prompts, meshes and client hooks) and are only moved and resized to the new base's node of the same name: `Base`, `PlotFloor`, `HomeZone`, `Slimes`, `Pad_1..8`, `MergeVat`, `LockButton` (with `Pedestal`), `Sign`, `SignLeg_1`, `SignLeg_2`, `LockBarrier` (with `Stopper`);
  4. the new slots get their meshes (`MeshSwap.applyUnder`), every slime on a pad is placed again, and `BaseFloors.sync` builds the upper floors of the new base.
  Going back to the jar does the same with the jar's nodes from `WorldLayout.plot(i)`.
- **Upper floors and roof:** `BaseFloors` asks the plot's shape (`build`/`top` get the base). A shape may put its roof in the floor as "shown only while top" pieces (`JarFloor = f`, `JarShow = "top"`, `JarCollide` for colliders): the factory does. Or it keeps the top floor's own colliders in the plot's `TopColliders` folder, rebuilt on whichever floor is on top: the jar and the pagoda (its dome and tall turret).
- **Containment (one rule per base):** `Actions.insideJar`, `PlotLockGuard.insideJar` (and `SlimeGuardView`'s jar table) and `BaseFloors.evacuate` ask `BaseShapes.get(base).inside(f, x, z)`. The drop exit's owner check is unchanged otherwise (§5.3).
- **Lock:** `LockBarrier.Stopper` is the barrier in every base (moved and sized to the doorway). Each base names its door looks `StopperShut` / `StopperParked` on the plot: the factory's roll-down shutter (down / rolled up); the pagoda reuses the jar's round door, lock ring and `OpenDoorCollider`, moved along plot z from the jar's doorway to its own (`BaseShapes` `jarDoor`), and the jar's `FootLook`. With no `StopperShut` look the primitive stopper shows while locked (the fallback in `PlotDecor.applyLock`). When a plot locks or opens while a client watches, `src/visuals/client/LockMotion` moves the `StopperShut` mesh locally from the `StopperParked` pose to shut (or back), turning round the vertical axis the two poses share (a door on its hinge) and sliding where they share none (the shutter), and fades the `DoorRing` to its new colour. The server's colliders switch at once; only the look moves. A client that first sees a plot already locked shows it shut, with no motion. `OpenDoorCollider` exists only where the door swings (jar, pagoda).
- **Skins on other bases:** a non-jar base's tint-only pieces are value-grey meshes whose slot carries `ThemeRole = <role>` (`MeshTint` stays the jar's lock-ring tint); `MeshSwap` sets `MeshPart.Color` to `BaseShapes.tint(base, skin, role)` when it places the mesh and on every skin change (verified in Studio: Color multiplies the vertex colours). A few pieces are themed meshes instead (`<piece>@<skin>`, up to 3 per skin per base; the factory: foot, roof kit, storey dressing), and a piece only some skins have appears and goes with the skin. The slot plan, boxes and tints are generated from the kit (`BaseShapeData/<Name>Meshes`, `models/_<name>_meshes.py`); the mesh entries are a generated MeshAssets block (`tools/base_mesh_assets.py`). Each collider names the mesh that is its look (`MeshStandIn`), so it hides once that mesh lands and shows as a primitive if it never does.
- **See inside:** like the jar's glass, a thief outside must see the pads. The factory has tall glass bays from 2 to 13 studs above each floor; the pagoda's stalk wall is a frame of kerb, head band and posts round a glass ring. Their glass meshes (`factory_windows(_1)`, `pagoda_glass_<f>`) hold nothing solid; their slots carry `glass = true` in the slot plan, which `BaseShapes` turns into the jar's `MeshMaterial` / `MeshTransparency` (0.8) / `MeshCastShadow = false`. The wall colliders stay where the glass is (no hole without visible glass).
- **Client:** `PlotMascot` draws the jar mascot and ooze ring on `jar` plots only. The Skins menu gets a base row above the skins: each base with Equip / Equipped / "Rebirth N"; an Exclusive base not owned yet has a gold "Exclusive" tag and "Buy · R$<price>" (Roblox's prompt for `Base_<id>`, or the Exclusive shop on that base while the product is not on sale). More bases than fit in one row take two rows, scrolling sideways when needed.
- **Studio-only debug (in-memory store only, `server/StudioHooks`):** player attribute `PcwPlotBase` (base id) raises that player's rebirths to the base's gate, or for an Exclusive base adds it to the test save's `ownedStyles.plotBase`, and equips it; with `PcwPads` the upper floors build. The flag itself is forced with `ReplicatedStorage.PcwFlag_BaseShapes = true` (`FeatureOverride`).
