# 18. v21: weekly event rotation (2026-10-16)

**Status:** contract first. `Config.FEATURES.WeeklyEvents` (default `true`); `false` = no multiplier, no attribute (an existing value is cleared). Server-authoritative; no remote, **no save-format change**, nothing saved.

- **Schedule (`src/shared/WeeklyEvents`, `Config.WEEKLY`):** a pure function of unix time (UTC), so every server agrees; tests pass a fake `now`. Weeks are ISO weeks: Monday 00:00 to the next Monday 00:00 UTC (`weekIndex`, `isoWeek`). Intervals are half-open `[startsAt, endsAt)`.
  - **Saturday trait event:** `TRAITS[week % m]` (Lucky: x1.5 rarity luck) on `TRAIT_WEEKDAY` 6 from `TRAIT_START_HOUR` 18 UTC for `TRAIT_SECONDS` (2 h). Clamped to end inside its own week.
  - **Caps:** `WeeklyEvents` clamps each multiplier to `MAX_MULTIPLIER` (x2) whatever the config says. At most one trait event is active, and none overlap (`tests/WeeklyEvents.spec` simulates 21 days).
- **Shared API (for the events board):** `WeeklyEvents.current(now)` (the trait event while live), `next(now)` (the first event starting after `now`), `state(now)`, plus `Event = { kind, id, label, icon, week, startsAt, endsAt, luck }`.
- **Replicated attribute:** `workspace:GetAttribute(Constants.WEEKLY_EVENT_ATTRIBUTE)` (`"WeeklyEvent"`), written by `server/WeeklyEventService` (only when the value changes; re-checked at every boundary, at most every `SYNC_SECONDS`). Format `week|activeTraitId or -|traitEndsAt or 0|nextKind|nextId|nextStartsAt` (unix seconds); `WeeklyEvents.decode` parses it.
- **Effects:** applied at drop time in `Spawner.spawnOne` (wild fountain drops only; merges, Appraise and the Boss Slime are untouched). The trait multiplier stacks with the dawn / dusk modifier and Slime Rain by multiplication and is capped. The clock is `Spawner.unixTime` (default `os.time`; `tests/ServerFixtures` pins it to `nil` = no schedule so seeded specs never depend on the date).
- **Live admin events (§12):** a running admin `luck` event **replaces** the weekly effects (no stacking, so an admin's x3 / x4 stays exactly what they asked for): `spawnOne` skips the weekly multiplier while `world.adminEvent` is set, and they resume when it ends. The admin `rain` event does not set `adminEvent` (it calls `forceRain`), so weekly effects continue under it. The attribute keeps showing the schedule either way. Admin events and `Config.WEEKEND` (income) are independent.
