# PvP client (v22, FEATURES.PvP)

Client-side notes. The contract is CONTRACT.md §26.1, landing with #241.

**Status:** `false` = the client builds no PvP Instance, connects nothing and looks up no PvP remote (`ui/PvpMount.mount` returns nil). Client only: this section lists what the client reads and sends. The contract is CONTRACT.md §26.1 (PvP remote contract: remote names, `State.pvp`, `PvpEvent`, item fields; landing with #241); the server wiring (`Remotes`, `Types.State.pvp`, `Constants.PVP_EVENT`, `PvpService`) comes with PR A-E. Until then `Remotes.ACTIONS` has no PvP action and the client's send refuses locally.

- **Reads:** `state.pvp = { rank, owned = {[id]=true}, best = {Knockback?, Trap?, Blaster?}, equipped?, cooldowns = {[id]=endsAt}, shieldUntil?, safeZone? }` (nil = empty); the `PvpEvent` RemoteEvent under `ReplicatedStorage.Remotes` (found with FindFirstChild / ChildAdded, never WaitForChild) with kinds `Cooldown {itemId, duration, startedAt}`, `Shield {endsAt?}`, `SafeZone {zone, inside}` (`Effect` / `TrapPlaced` / `TrapCleared` are only forwarded, no FX yet); the Player attribute `PvpShieldUntil`; item data from `Config.PVP_TOOLS` (else `PvpClient.STUB_CATALOG`, a stub with the same ids and §26.1's field names; #241's Config currently still says `slow` (0.3) / `traps`, the UI text reads both). All times are server time.
- **Sends** (through the existing `Request` path, `ctx.send`): `EquipPvpItem(itemId?)` and `UsePvpItem(itemId, targetUserId?, aim?)`. A refusal is a toast; the client starts no cooldown and equips nothing by itself: the ring and the equipped rim only follow `State.pvp` / `PvpEvent`.
- **Rules (UI hints only, the server decides):** cooldown = a `Cooldown` event starts the ring (`startedAt + duration`); `state.pvp.cooldowns[id]` (endsAt) is the fallback and the resync: a snapshot that lists the id replaces the event's end (shorter or longer), a snapshot that omits it drops an event older than `PvpClient.EVENT_GRACE` (1 s) and keeps a younger one; ids never seen in an event follow the state. Shield = a `Shield` event over `state.pvp.shieldUntil` over the `PvpShieldUntil` attribute (a snapshot clears the event). Safe zone = `state.pvp.safeZone` (join / Sync) and `SafeZone {zone, inside}` events only, no client position check. Unlocks = catalog items with `rebirths <= rank` (`PvpClient.unlockedAt`). `PvpClient.BASE_SLAP` ("Base slap", Knockback rank 0, free) is display-only for the shop: not a catalog entry, not a hotbar slot; the SLAP! button stays the way to slap. The custom hotbar never touches Backpack or Tools.
- **UI (`ui/PvpClient` adapter, `ui/PvpHudLogic` maths + boxes, `ui/PvpHud` views, `ui/PvpMount` flag gate and wiring):** a bottom hotbar above the carry / tutorial cards (`PvpHudLogic.hotbar`: best Knockback, Trap, Blaster, then the owned fun items; keys 1-9, more slots scroll; tap = equip, tap the equipped slot = use), a cooldown ring (two half masks with a rotated UIGradient) with seconds above 1 s, a new-player shield chip (m:ss) and a safe-zone chip in the Banners stack (LayoutOrder 11 / 12). GUI objects under the ScreenGui only, nothing in Workspace.
- **Icons:** one placeholder tile per `Config.PVP_TOOLS` id (else the stub's 19 ids), name from the catalog entry, in `ItemIcons` group `pvp` until the art is pasted into `ItemIcons.IMAGES` (listed in `ITEM-ICONS-NEEDED.md`).
- **Studio preview:** `PcwFlag_PvP = true` (ReplicatedStorage, `FeatureOverride`) turns the flag on; `SlimeUI.PcwPvpStub = <rank>` fakes `state.pvp` for that rank while the server sends none.
