# PvP client (v22, FEATURES.PvP)

Client-side notes. The contract is CONTRACT.md §26.1, landing with #241.

**Status:** the server is on main (#241, CONTRACT.md §26.1; design in `docs/PVP.md`). `false` = the client builds no PvP Instance, connects nothing and looks up no PvP remote (`ui/PvpMount.mount` returns nil). With it on, the client reads `State.pvp` and the `PvpEvent` remote and sends `EquipPvpItem` / `UsePvpItem` through the normal `ctx.send` / `Request` path. No stub data ships in `src/`; test doubles live in `tests/ui/PvpFixtures.luau`.

- **Reads:** `state.pvp = { rank, owned = {[id]=true}, best = {Knockback?, Trap?, Blaster?}, equipped?, cooldowns = {[id]=endsAt}, shieldUntil?, safeZone? }` (`Types.PvpView`; nil = empty; `safeZone` is `"Spawn" | "Shop" | "Fountain"`); the `PvpEvent` RemoteEvent (`Constants.PVP_EVENT`) under `ReplicatedStorage.Remotes` (found with FindFirstChild / ChildAdded, never WaitForChild) with kinds `Cooldown {itemId, duration, startedAt}`, `Shield {endsAt?}`, `SafeZone {zone, inside}` (`Effect` / `TrapPlaced` / `TrapCleared` are only forwarded, no FX yet); the Player attribute `PvpShieldUntil`. Item data is `Config.PVP_TOOLS` only; rank gates go through `Shared.PvpRules.isUnlocked`. `best` is taken as the server sent it (no client supersede rule); `equipped` comes from `State.pvp` (the server sends a snapshot after every Equip, so the `PvpEquipped` attribute is not read). All times are server time.
- **Config names:** main's Config says Blaster `slow` (a fraction, 0.3) and Trap `traps`, and a trap's `cooldown` is its rearm. §26.1's prose lists `slowPercent` / `count` / `rearm`; nothing on main uses those, so `PvpClient.effectSlowPercent` / `effectCount` read `slow * 100` / `traps` only.
- **Sends** (through the existing `Request` path, `ctx.send`, args as §26.1): `EquipPvpItem(itemId?)` and `UsePvpItem(itemId, targetUserId?, aim?)`. A refusal is a toast; the client starts no cooldown and equips nothing by itself: the ring and the equipped rim only follow `State.pvp` / `PvpEvent`.
- **Rules (UI hints only, the server decides):** cooldown = a `Cooldown` event starts the ring (`startedAt + duration`); `state.pvp.cooldowns[id]` (endsAt) is the fallback and the resync: a snapshot that lists the id replaces the event's end (shorter or longer), a snapshot that omits it drops an event older than `PvpClient.EVENT_GRACE` (1 s) and keeps a younger one; ids never seen in an event follow the state. Shield = a `Shield` event over `state.pvp.shieldUntil` over the `PvpShieldUntil` attribute (a snapshot clears the event). Safe zone = `state.pvp.safeZone` (join / Sync) and `SafeZone {zone, inside}` events only, no client position check. Unlocks = catalog items with `rebirths <= rank` (`PvpClient.unlockedAt`). `PvpClient.BASE_SLAP` ("Base slap", Knockback rank 0, free) is display-only for the shop: not a catalog entry, not a hotbar slot; the SLAP! button stays the way to slap. The custom hotbar never touches Backpack or Tools.
- **UI (`ui/PvpClient` adapter, `ui/PvpHudLogic` maths + boxes, `ui/PvpHud` views, `ui/PvpMount` flag gate and wiring):** a bottom hotbar above the carry / tutorial cards (`PvpHudLogic.hotbar`: best Knockback, Trap, Blaster, then the owned fun items; keys 1-9, more slots scroll; tap = equip, tap the equipped slot = use), a cooldown ring (two half masks with a rotated UIGradient) with seconds above 1 s, a new-player shield chip (m:ss) and a safe-zone chip in the Banners stack (LayoutOrder 11 / 12). GUI objects under the ScreenGui only, nothing in Workspace.
- **Icons:** one placeholder tile per `Config.PVP_TOOLS` id name from the catalog entry, in `ItemIcons` group `pvp` until the art is pasted into `ItemIcons.IMAGES` (listed in `ITEM-ICONS-NEEDED.md`).
- **Studio preview:** `PcwFlag_PvP = true` (ReplicatedStorage, `FeatureOverride`) turns the flag on in the client; the server decides `State.pvp`, so the preview needs a server with `FEATURES.PvP` on too (no client-side fake data).
- **Tests:** `tests/ui/PvpClient.spec` (adapter, cooldown math + resync, shield / safe-zone precedence, lock state per `REBIRTH_TIERS` rank vs `PvpRules.isUnlocked`), `PvpMount.spec` (flag gate, wiring), `PvpHudLayout.spec` (all gate + landscape viewports), `PvpContract.spec` (every event kind / `State.pvp` field exists on the server side, and the real `PvpService` output drives the adapter), fixtures in `tests/ui/PvpFixtures.luau`.
